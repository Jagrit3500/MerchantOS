# MerchantOS codebase audit

Reviewed and remediated through 12 September 2026.

## Scope and hardcoding boundary

The audit covered the Python and JavaScript application code, HTML/CSS, configuration, local policy sources, ingestion pipeline, sample data, launcher, and documentation. Generated bytecode and third-party packages were excluded; the Chroma index was rebuilt from the reviewed policy files.

"Nothing hardcoded" is treated as: no secrets in source, no duplicated deployment/provider settings in consumers, and no mutable financial or workflow thresholds embedded in application logic. Intentional code constants remain in source, including schemas, accepted CSV aliases, UI text, algorithms, CSS design tokens, and sample fixtures. Moving those values into environment variables would make the code harder to validate without improving deployability.

## Regulatory-content correction

Earlier copy incorrectly treated a provider's common T+2 schedule and several internal response targets as universal RBI deadlines. The reviewed implementation now separates three things:

1. RBI requirements from the official 2025 Payment Aggregator Master Direction.
2. Provider policy and the merchant agreement.
3. Operator-configured audit and follow-up targets.

The app now uses RBI/DPSS/2025-26/141 paragraph 8 for the merchant-issues officer and published escalation matrix, paragraph 13 for merchant due diligence, paragraph 15 for permitted assisted due diligence, and paragraph 16/Table 1 for transparent settlement timing in the PA-merchant agreement. It does not describe T+2, 24 hours, five days, or thirty days as a universal statutory merchant-resolution deadline.

Consumer/Ombudsman drafts now require eligibility and jurisdiction checks. Legal output is explicitly a counsel-review draft and no longer promises an automatic consumer-forum remedy.

Primary reference: <https://www.rbi.org.in/Scripts/BS_ViewMasDirections.aspx?id=12896>

## Remaining limitations

- A valid Google Auth Platform **Web application** client must be created in the project console and stored only in `.env`. Google intentionally creates this credential through its Auth Platform UI; IAM Workforce OAuth clients are not interchangeable.
- Policy/provider documents are dated snapshots and require periodic expert review.
- Business-day calculations exclude weekends but do not contain a regional bank-holiday calendar.
- Citation validation alone does not prove logical entailment for optional generated answers outside Agent 1. Agent 1 avoids this limitation by displaying extractive policy evidence.
- Only the latest reconciliation summary is shared as live case data across services. Agent 1 completed diagnoses can be reconstructed from their saved answers; reconciliation and escalation history currently navigate to their originating workspace without reconstructing complete historical form state.
- Roles, tenant isolation, password recovery, automated backups, provider APIs, automatic complaint submission, and production deployment hardening remain outside this local prototype.
